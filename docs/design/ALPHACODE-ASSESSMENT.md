# AlphaCode integration decision

Date: 2026-10-12. Status: source research and implementation decision; no installation, inference or desktop/browser actions performed.

## Selection

Use [dragonked2/alphacode](https://github.com/dragonked2/alphacode/tree/2a1d17156282e59fa811ceb58d9e28302d360fba), pinned to `2a1d17156282e59fa811ceb58d9e28302d360fba`, package/release `1.0.79`. This is the terminal coding assistant, not DeepMind's competition-code research system. Upstream provides Linux x86_64 release archives and checksums. It is MIT-licensed; dependency and Firefox-extension notices require separate checks before distribution.

Add it as a genuine, separately supervised harness. Do not merge its daemon, provider registry, memory, swarm coordinator or updater into Ironbark's local core. Its browser/web and Linux accessibility tools add useful capabilities, but a longer tool list does not establish a complete assistant: shared conversations, knowledge, approvals, recovery and qualified integrations still have to be built.

## Required adapter work

1. Maintain a small, pinned upstream patch series, not a wholesale application fork. Add a task-bound permission gate to the actual native tool dispatch boundary, fail closed before every sink, and carry requests/replies through native daemon and ACP transports. Inspect all direct execution call sites with LSP before patching; route them through the same gate. Ship no unguarded alternate dispatch path.
2. Negotiate `ironbark.permissionsVersion = 1` and report effective route, cwd and tool set. Refuse unattended use if the binary lacks this extension, identity differs, the daemon is unrelated, or enforcement is incomplete.
3. Keep AlphaCode's actual tools and native sessions. Return real tool outputs, text replacements, interruptions, errors and session IDs. AlphaCode's internal swarm remains disabled until delegated-child limits and telemetry are enforceable; Ironbark performs ordinary multi-worker orchestration itself.
4. Launch a dedicated daemon/ACP pair in the qualified worker environment. Disable self-development, update checks/automatic updates and telemetry. Scrub the environment and isolate config/data/runtime paths. Default MCP, browser and desktop capabilities absent; enable only the authorised tool set, not `*`.
5. Browser/desktop automation is part of the requested assistant integration, with separate user-presence and consequential-action gates. It is not silently enabled by adding the harness. Use an action-specific broker so a whole desktop-session bus or private browser authority is not exposed to an arbitrary coding worker.
6. Qualify filesystem escape, command network access, permission denial, stale approval, child execution, process shutdown, provider pins, browser isolation and actual Linux accessibility behavior before advertising availability.

## Current evidence limits

Source inspection establishes implemented capabilities and integration hazards, not runtime reliability. No AlphaCode executable was installed or run. The current ACP bridge alone cannot satisfy Ironbark's unattended-mutation contract. The planned permission extension and containment are real implementation work and release gates, not assumed existing features.

Additional workstation prerequisites checked during planning: Hermes ACP imports pass `hermes acp --check`; unprivileged user/PID/network namespaces can launch with Bubblewrap. This does not prove a final worker sandbox. Rust has no installed/default toolchain, and `webkit2gtk-4.1`/`javascriptcoregtk-4.1` are absent from pkg-config. Current root filesystem has 429 GiB available (10% used); older filesystem-pressure memory is stale.
