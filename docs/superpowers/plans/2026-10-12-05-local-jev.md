# Local JEV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Use the existing local judgment runtime for typed, domain-qualified assistant advice without mistaking availability, token scores or model prose for authority.

**Architecture:** Reuse File Steward's existing llama.cpp process/model, not a second server or paid judging service. A strict adapter reads raw completion/identity and preserves invalid/abstained/unqualified states rather than inheriting the facade's enum coercion. Core applies deterministic eligibility first and retains all judgment provenance.

**Tech Stack:** Existing facade `127.0.0.1:8420`, existing llama.cpp `127.0.0.1:8091`, active observed Qwen2.5-0.5B-Instruct-Q8_0.gguf; TypeScript adapter, Rust core, versioned domain fixtures and offline evaluation.

**Spec:** [design](../../design/DESIGN.md) §8; [retained real smoke](../../design/jev-smoke.json); [master](2026-10-12-ironbark-assistant.md).

## Global Constraints

- Do not start another competing llama-server or change File Steward's active model as part of ordinary assistant work.
- JEV is consulted only for semantic uncertainty; it cannot turn a failed check into success or authorize a disallowed option.
- No paid judging service is used as a silent fallback.
- `available`, `invalid`, `abstain`, and `unqualified` are distinct.
- Invalid/truncated outputs, missing meaningful scores, unknown model state, and service failures do not become the first enum choice or an invented high-confidence answer.

## Review Focus

1. Prefix/truncated/empty output: invalid, never default to the first enum candidate (J1).
2. First-token/shared-prefix scores or missing probabilities: no invented calibrated confidence (J1/J2).
3. Wrong model/prompt/dataset version or unavailable loopback service: invalidate qualification without paid fallback (J1/J2).
4. Ambiguous or adversarial semantic input: abstain and retain honest coverage/error evidence (J2).
5. JEV chooses a forbidden route or declares unverified work complete: deterministic core denial wins (J3).
