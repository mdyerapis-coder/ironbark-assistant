# Local Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a real local authority with durable commands/events, exact approvals, contained process ownership, recovery and consistent backups.

**Architecture:** Rust core, one transactional SQLite store and one scheduler. CLI and desktop connect to the same user-scoped Unix socket; neither writes its own execution database. SQLite work runs on a dedicated bounded store thread, not blocking Tokio's executor.

**Tech Stack:** Rust 1.98.1, Tokio, rusqlite (bundled SQLite/FTS5), serde, schemars, ts-rs, SHA-256, UUID, Bubblewrap, Linux process groups and peer credentials.

**Spec:** [design](../../design/DESIGN.md) §§3,9,10; [master contracts](2026-10-12-ironbark-assistant.md).

## Global Constraints

- The local core is the only scheduler and approval authority.
- Credentials stay outside the frontend, prompts, retrieval index, logs, and exports.
- No telemetry or public listener by default.
- One writer owns each worktree; shared edits go through one integration owner.
- Cancellation terminates the owned process group, verifies termination, and preserves partial artifacts.
- No existing OMP/Codex/OpenCode sessions, credentials, project files, or global configuration are overwritten to make the new client work.

## Review Focus

1. Reconnect/repeated command IDs: recover committed events without duplicate dispatch (C1).
2. Changed target, diff, policy, expired/revoked approval: deny before the sink (C2).
3. Symlink/nonexistent-tail/shell escape and direct networking: enforce actual boundaries, not lexical prefixes (C3).
4. Core crash after mutation but before receipt: block and reconcile, never automatic replay (C4).
5. Backup/restore with missing objects, secrets or active runs: atomic integrity failure or stopped restoration (C5).
