# Changelog

## Unreleased

- Added the local Rust daemon, private Unix IPC and CLI for projects, status, diagnostics, durable events and shutdown.
- Added transactional request identity: identical replay returns the original reply; changed commands cannot reuse a request ID; interrupted accepted work is not automatically redispatched.
- Added Rust-generated protocol-1 contracts and bounded event replay with precommit credential redaction.
- Enforced unknown-field rejection for payload-free tagged commands and approval decisions; Serde unit variants were insufficient for this boundary.
- Added native exact-action grant and directory-relative file-write primitives, with owner command integration through the service dispatcher.
- Added policy enforcement for exact actions (digest over canonical arguments), single-use durable grants, and the openat2 directory-relative file sink (BENEATH, no magic links, regular single-link files only, nonblocking FIFO refusal, identity re-observation before truncation).
- Added C5 objects: content-addressed artifacts, additive import preview/apply, bounded artifact reads, online snapshot backup, offline stopped restore into a fresh namespace, conservative reference-aware retention and published CAS capacity.
- Added P2 conversation-tree operations: create, history, rename, search, export, message edit, queue turn, regenerate, archive and delete, with the frame request id as the stable turn identity.
- Added CLI named subcommands for the C1/C5/P2 surface plus a generic `command '<CoreCommand JSON>'` dispatch; every subcommand prints exactly one JSON DTO on stdout.
- Added the network lease boundary (deny-by-default, run-pinned, broker-socket re-validated against device/inode, credential-scope header allowlist) and the process namespace boundary: dedicated `namespace_bridge` runner, owned bwrap namespaces, private `/home/worker` + `/run/worker` tmpfs only, non-recursive read-only remounts of `/`, `/home`, `/run`, nondumpable + no_new_privs + TSYNC seccomp denying ptrace/process_vm/pidfd_getfd/x32, pidfd identity tracking and the private fd 3 control channel.
- Corrected worker containment to be runtime-immutable: mounted source roots under `/home/worker` are rejected, and a regression test denies runtime-ancestor rename and substitution of a mounted source via actual process evidence.
- Stopped provider SDK transport retries at the first failed dispatch. Transport failure remains failure, not a user cancellation or another-account fallback.
- Added the TS provider adapter (registry, OMP-SDK, local, custom) with connection pinning, credential-lease resolution over the private fd 3 binary channel, composed cancellation/watchdog signals, output ceilings and exact one-to-one native replay, and the JEV client with strict raw decoding, explicit abstention and abort-on-every-exit.
- Redacted complete raw Cookie/Set-Cookie header values and folded continuation lines before SQLite persistence.
- Prevented completed Shutdown UUID replay from terminating a replacement daemon while preserving the durable reply.
- Acquired a held data-directory authority lock before store recovery, preventing two runtime directories from serving the same store concurrently.
- Rejected unsafe writable or symlinked private-path ancestry and used held directory descriptors for private files and SQLite initialization.
- Added C4 run scheduling and crash reconciliation: `run create` mints the durable job/node/run chain (born `queued`, admitted to `ready` through the transition table), `run start` records the native session, partial artifacts and the observed process identity (pid + boot start ticks), `run checkpoint` captures a phase-tagged checkpoint as a CAS object, and `run inspect`/`run reconcile` apply an owner decision. Native completion parks the run in Reviewing; only an accepted, passing post-verification checkpoint reaches Succeeded, and a cancel request is not a stop receipt.
- Corrected three C4 defects found by the live smoke: `RunBodyMeta` used `deny_unknown_fields` while reading a run body that also carries `task`/`artifacts` (so the recorded process identity was always dropped), `active_scope_for` fell back to a stale Active automation scope after its release (release now revokes authority), and `RunControl::start` could not admit the `queued` run it documents.
- Fixed knowledge deletion: `delete_source` removed the revision row while the metadata sentinel chunk still referenced it, so every deletion failed on the foreign key; the whole revision (including the sentinel) is now removed and a deleted citation resolves an explicit `Deleted`.
- Fixed the citation-open contract: `KnowledgeOpenCitation` carries a `Citation` (not an opaque chunk id), so `CitationResolver::open` shares exactly one resolution path with `KnowledgeService::open_citation_in` and `Deleted` is reachable.
- Fixed the J2 Clopper-Pearson upper bound: the log-domain binomial term divided by `ln(p)` instead of `ln(1-p)`, so a zero-error holdout reported ~0 instead of the rule-of-three bound; the 3/80 case now reports the true 9.4% bound (the old test asserted 4.9%).
- Fixed HTML extraction for inline tags: the sanitised text kept `<b>`/`<i>` markup, so paragraph content was not plain text; a final tag-strip pass now runs before section/paragraph units are emitted.
- Completed the protocol exporter so `generated.ts` typechecks: the fixed emit list omitted four transitively referenced DTOs (`EvaluationReportInput`, `HoldoutMetrics`, `WebGptActivationState`, `WebGptSubmissionState`, `ActionOutcome`) and leaked ts-rs's `JsonValue` for the automation accessibility blob.
- Fixed `qa/smoke/crash-recovery.ts` to drive the real surface: byte-chunk decoding instead of `Buffer` events on Bun `ReadableStream` pipes, one sandbox environment for both the daemon and the CLI (previously the CLI inherited the developer's XDG paths and talked to whatever daemon was already running), UUID request identities, a kind-tagged import document, raw artifact bytes from `artifact read`, and boot-tick start times so a live owned process is not reported as a recycled PID.
- Added the genuine OMP harness adapter (`omp acp` over stdio, global `--profile` before the subcommand, managed HOME/XDG roots and a dedicated profile so a worker never touches the operator's OMP auth, sessions or settings). `omp/18.8.9` is probed from the installed CLI and reported as `unqualified` until a live smoke qualifies it.
- Fixed three native-boundary defects found by the new tests: `WorkspaceService::integrate` piped the diff into `git apply --check` via `Command::output()`, which hands the child an empty patch and made every integration fail with "No valid patches in input" (the check and apply now share a helper that writes the diff and closes stdin); the integration commit set `GIT_AUTHOR_DATE=now`, which git rejects, so a successful apply could never be committed; and `checkTurnBudget` validated the *policy's* tool list instead of the turn's, so a turn handed no tools would have run with none declared (now refused as `ManagedTurnToolsRequired`).
- Verified on this workstation: 168 core Rust tests passing (23 unit + 145 integration across durability, approval, containment, conversation, dispatch, recovery, lifecycle, automation, knowledge and backup), 105 adapter tests passing, protocol-1 contracts regenerated with a clean strict `tsc` type check of `generated.ts`, and the crash-recovery smoke passing end to end against the real daemon and CLI (kill before write and kill after write/before receipt; blocked reconciliation; `accept_observed` refused without a post-verification checkpoint; no duplicate write; artifact and checkpoint CAS objects preserved).
- Added H2–H5 and H8 adapter boundaries with provider-free tests: `codex-session.test.ts` (real generated bindings under `src/native/codex-schema/` from `codex app-server generate-ts`, pinned with a per-file digest record; resume identity/route mismatch dispatches nothing, an unrecognised server request is answered `{denied:true}`, a late failed tool item never reports `succeeded`, and `interrupt()` only resolves from an observed process exit), `opencode-session.test.ts`, `claude-permissions.test.ts`, `hermes-permissions.test.ts` and `native-boundaries.test.ts`, all driven by real executable process doubles rather than mocks.
- Fixed four harness defects the new tests found: `claude.ts` never validated managed settings before launch (a malformed or dangerous `settings.json` now refuses with a typed error and spawns nothing) and passed `--permission-prompt-tool` with no value, swallowing the next flag as its argument (now `--permission-prompts host`); `codex.ts` derived the turn outcome only from the completion frame, so a failed tool still reported success, and resolved `interrupt()` before the native process was observed exiting; and `checkTurnBudget` validated the policy's tool list instead of the turn's.
- Added H6: deterministic DAG admission (`scheduler/{graph,budgets,handoffs}.rs` — cycle/duplicate/unknown-role/route/pin rejection before any dispatch, dependency-ordered run creation under a `TaskAuthority`, a default two-worker admission budget that queues the third, and disclosure-filtered handoffs that never carry a fabricated native session), role registry + per-harness activation rendering, a scoped tool registry with recorded exclusion reasons, and a local stdio MCP connector that fails closed without activation. Canonical `WorkspaceMode`, `JobGraph`, `JobNode`, `RoleDefinition` and `DelegatedLimits` DTOs now live in the contract module and are exported to TypeScript.
- Added J3 advisory judgments (`judgments/advisory.rs`): deterministic policy and the qualification gate are applied before any semantic judgment, an unqualified/absent domain yields `Unavailable` rather than a choice, a judgment can never add an ineligible route or grant scope, and an outage calls no paid judge. `AdvisoryOutcome::NeedsPlanner` now carries the optional recorded `decision_id` the plan specifies.
- Added WebGPT verification (`webgpt_activation.rs`): non-activated states are distinct and refuse turns, a drifted profile digest is detected rather than reused, a duplicate submission returns the stored receipt with no second send, an ambiguous send reconciles explicitly and is never auto-resent, and a WebGPT failure leaves the resolved route unchanged.
- Added the AlphaCode integration artifacts: `integrations/alphacode/source.json` pins commit `2a1d17156282e59fa811ceb58d9e28302d360fba` with per-file pristine/patched digests and a source-recipe digest, `build.sh` fetches that exact revision, verifies the notices, rejects any patch absent from the pin, applies the series in order with per-patch sha256 prechecks and refuses a digest mismatch, `NOTICE` carries the upstream MIT notice, and `patches/0001-ironbark-permission-boundary.patch` (103 files) adds the fail-closed permission gate plus `--ironbark-managed`. Re-verified here: the pinned checkout at `.sources/alphacode` carries the series and it reverses cleanly, so the patch matches the tree.
- Added the release gate: `qa/qualification/release.ts` (binds each required gate to a real receipt — `state`, `command`, optional `manifest_version`/`manifest_sha256`/artifact digests recomputed from the tree; a missing, unreadable or non-passing receipt blocks and never throws, and an empty required list is itself blocked) and `qa/qualification/run-gates.ts` (executes each gate, captures the real exit code and output tail, and writes receipts with digests only for the artifact observations specified; an unspawnable gate is recorded failed, never passed).
- Repaired every smoke script and harness adapter that was written against earlier APIs: the whole repository now passes `bunx tsc --noEmit` with zero errors (it previously reported 102), and the provider-dependent live harness round-trip is now explicitly gated behind `IRONBARK_LIVE_HARNESS=1` with a printed reason instead of failing on a host with no configured provider.
- Verified end to end after this wave: the release gate runner executed all seven required gates and the checker bound every one of their receipts against the tree — `bun qa/qualification/run-gates.ts` exited 0 with 7/7 gates passed (`cargo test --workspace`, `bun test packages/adapters/test`, `bunx tsc --noEmit`, and the crash-recovery, core-reconnect, backup-restore and worker-containment smokes) and `bun qa/qualification/release.ts --manifest packaging/manifest.json` reported `state: passed` with exit 0.
- Verified after this wave: 201 core Rust tests passing (0 failing suites; adds `job_graph`, `role_authority`, `judgment_authority` and `webgpt_activation`), 137 adapter tests passing with the live round-trip skipped by explicit opt-in, zero `tsc` errors, and the release gate reporting `blocked` with exit 1 against the real manifest because no receipt yet satisfies its convention. `crates/ironbark-core/tests/worktree_ownership.rs` (one writer per worktree, readers coexist, foreign-run refusal, integration requires passing review *and* verification receipts, a failed receipt is never overwritten, a diff that changed after the approved description cannot integrate, release removes the worktree and never the original) and `packages/adapters/test/native-boundaries.test.ts` (capability honesty for every adapter — never `qualified` without a live smoke, unavailable binaries reported rather than substituted, no fabricated sessions/events, permission actions bound to the session's run/project/policy version, policy drift and empty tool lists refused, sandbox posture derived from policy).

The runtime documentation now covers the local core, permissions and policy, worker containment and provider/judgment boundaries, plus run scheduling and crash reconciliation.
